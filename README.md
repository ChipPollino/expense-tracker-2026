# Expense Tracker
Expense Tracker — прикладное веб-приложение для учета личных расходов и планирования бюджета.

Проект разработан в рамках индивидуальной работы и демонстрирует создание полноценного веб-приложения на FastAPI с разделением кода на слои, асинхронным взаимодействием с PostgreSQL, авторизацией через cookie-сессии, аналитикой и HTML-интерфейсом.

## Назначение приложения
Приложение предназначено для пользователей, которые хотят:

* вести учет повседневных расходов;
* распределять траты по собственным категориям;
* анализировать расходы за выбранный период;
* контролировать месячный лимит;
* просматривать статистику в наглядном виде.

## Основные возможности

### Авторизация и профиль
* регистрация пользователя;
* вход в аккаунт по email и паролю;
* выход из аккаунта;
* авторизация через cookie-сессии;
* безопасное хранение хеша пароля;
* смена пароля;
* редактирование профиля;
* полное удаление аккаунта вместе со связанными данными.

### Категории расходов
* создание пользовательских категорий;
* просмотр списка категорий;
* переименование категории;
* удаление категории;
* запрет удаления категории, если она используется в расходах.

Каждый пользователь работает только со своими категориями.

### Расходы
* добавление расхода;
* указание суммы, категории, даты и необязательного описания;
* просмотр списка расходов;
* редактирование и удаление записей;
* фильтрация по категории, диапазону дат и сумме;
* сортировка по дате, сумме и названию категории.

### Аналитика
* общая сумма расходов за период;
* количество записей о расходах;
* статистика по категориям;
* помесячная статистика;
* графическое отображение данных на странице приложения.

### Настройки
* переключение светлой и темной темы;
* установка и сброс месячного лимита расходов;

## Хранимые данные
Приложение использует следующие таблицы:

### `users`
Хранит данные пользователей:
* имя;
* email;
* хеш пароля.

### `categories`
Хранит пользовательские категории расходов:
* название категории;
* идентификатор владельца.

Название категории уникально в пределах одного пользователя.

### `expenses`
Хранит записи о расходах:
* сумма;
* дата;
* описание;
* категория;
* пользователь.

### `settings`
Хранит настройки пользователя:
* тема оформления;
* месячный лимит расходов.

Для каждого пользователя создается одна запись настроек.

## Архитектура
Проект построен по принципу layered architecture:

Frontend → Router → Service → Repository → Database

### Router
* HTTP-endpoints;
* получение входных данных;
* dependency injection;
* преобразование бизнес-ошибок в HTTP-ответы.

### Service
* бизнес-логику;
* проверки;
* управление транзакциями;
* хеширование и проверку паролей;
* подготовку данных для ответа.

### Repository
* выполнение SQL-запросов;
* добавление, получение, обновление и удаление записей;
* агрегирующие запросы для аналитики.

### Models
Описывают структуру таблиц PostgreSQL и связи между ними через SQLAlchemy ORM.

### Schemas
Описывают входные и выходные данные приложения и выполняют их валидацию через Pydantic.

## Установка и запуск

### 1. Клонировать репозиторий
git clone <repository-url>
cd expense-tracker-2026

### 2. Создать виртуальное окружение
python -m venv .venv

Активировать окружение на Windows:
.venv\Scripts\activate

Активировать окружение на Linux или macOS:
source .venv/bin/activate

### 3. Установить зависимости
pip install -r requirements.txt

### 4. Создать файл `.env`

В корне проекта создать файл `.env`
env
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASS=your_password
DB_NAME=expense_tracker
SECRET_KEY=your_secret_key

Для генерации `SECRET_KEY` можно использовать:
python -c "import secrets; print(secrets.token_urlsafe(32))"

### 5. Создать таблицы
python -m src.scripts.create_tables

### 6. Запустить приложение
uvicorn src.main:app --reload

После запуска приложение будет доступно по адресу:
http://127.0.0.1:8000/

## Безопасность
В проекте реализованы:
* хранение только хешей паролей;
* авторизация через подписанные cookie-сессии;
* проверка текущего пользователя через dependency;
* изоляция данных пользователей по `user_id`;
* защита от изменения и удаления чужих данных;
* транзакции с `commit()` и `rollback()`;
* валидация входных данных;
* уникальность email;
* уникальность названий категорий в пределах пользователя.
